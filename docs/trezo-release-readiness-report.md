## 1. الملخص التنفيذي

يهدف هذا التقرير إلى توثيق صلاحية نظام TREZO للتشغيل الرسمي في إدارة طلبات الصرف ودورة الاعتماد والطباعة والتدقيق. لا يُعد نجاح البناء البرمجي وحده دليلاً كافياً على الجاهزية؛ إذ يجب أن تنجح اختبارات التشغيل الخمسة في بيئة مماثلة للإنتاج، وأن تعتمد الإدارة بيانات الشركة والحسابات ومسار الاعتماد.

**القرار المقترح حالياً:** جاهزية تقنية جيدة للإصدار 63f7f2f7، مع بقاء الاعتماد الرسمي مشروطاً بإكمال اختبارات القبول الواقعية T1–T5، إدخال بيانات الشركة النهائية، والتحقق من النسخة الاحتياطية والاستعادة.

## 2. نطاق التقييم

يشمل التقييم إنشاء طلبات الصرف وتعديلها وإرسالها، قناتي الصراف والبنك، العملات والسنوات المالية، مسار الاعتماد المرن، الحسابات المحلية والصلاحيات، سجل التدقيق، معاينة وطباعة القوالب الأربعة، والاستجابة على الكمبيوتر والجوال.

ولا يشمل هذا التقرير اعتماد مبالغ مالية حقيقية أو تكاملات بنكية خارجية أو مراجعة قانونية مستقلة أو اعتماد سياسة محاسبية للشركة.

## 3. أدوات الاختبار الآلي المقترحة

| الأداة | الاستخدام في TREZO | مستوى الأولوية |
|---|---|---|
| **Vitest** | اختبارات الخادم، إجراءات tRPC، قواعد الصلاحيات، والتحقق من وظائف المكونات. | مستخدمة حالياً / أساسية |
| **React Testing Library** | اختبار سلوك الواجهة كما يراه الموظف، مثل إظهار زر الاعتماد أو منع التعديل. | مستخدمة أو مناسبة للتغطية الحالية |
| **Playwright** | أتمتة المتصفح لاختبار الدخول، إنشاء الطلب، تبديل الحسابات، الاعتماد، والطباعة في متصفح حقيقي. | الإضافة الآلية الأهم |
| **axe-core** | فحص آلي أولي لإمكانية الوصول، وضوح العناصر، وتسميات الحقول. | مفيدة قبل التسليم |
| **Lighthouse** | قياس الأداء والاستجابة ومشكلات الواجهة العامة. | فحص مساند وليس بوابة مالية |

لا تستبدل هذه الأدوات اعتماد الإدارة للاختبار التشغيلي؛ فهي تسرّع التكرار وتقلل الأخطاء البشرية، لكنها لا تعتمد صحة بيانات الشركة أو السياسة المالية.

المراجع الرسمية: [Vitest](https://vitest.dev/guide/)، [Playwright](https://playwright.dev/docs/intro)، [React Testing Library](https://testing-library.com/docs/react-testing-library/intro/)، [axe-core](https://github.com/dequelabs/axe-core)، [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview).

## 4. سجل اختبارات التشغيل الخمسة

### T1 — طلب صرف عبر قناة صراف

**الهدف:** إثبات إنشاء طلب نقدي دون حساب بنكي.

**بيانات الاختبار:** شركة تجريبية، مستفيد تجريبي، مبلغ [ ]، عملة [ ]، سنة مالية [ ].

**خطوات التحقق:** تسجيل الدخول بالمحاسب، إنشاء الطلب، اختيار قناة صراف، ترك الحساب البنكي دون اختيار، حفظ المسودة، إرسالها للمراجعة، ثم مراجعة التفاصيل.

**معيار القبول:** يُقبل الطلب دون حساب بنكي، وتظهر قناة الصراف في التفاصيل والطباعة، ويُسجل الإنشاء والإرسال في سجل التدقيق.

**النتيجة:** [ناجح / فاشل] — **المرجع:** [ ] — **الدليل:** [رابط لقطة أو ملف]

### T2 — طلب صرف عبر قناة بنك

**الهدف:** إثبات إلزام الحساب البنكي الصحيح للمستفيد.

**بيانات الاختبار:** شركة [ ]، مستفيد [ ]، بنك [ ]، حساب/IBAN منتهي بـ [ ]، مبلغ [ ]، عملة [ ].

**خطوات التحقق:** إنشاء طلب، اختيار قناة بنك، محاولة الحفظ دون حساب لإثبات الرفض، اختيار الحساب المرتبط بالمستفيد، الحفظ والإرسال، ثم مراجعة التفاصيل والمستندات.

**معيار القبول:** يرفض النظام الطلب دون حساب، ويقبله بعد اختيار الحساب الصحيح، ولا يعرض حساب مستفيد آخر.

**النتيجة:** [ناجح / فاشل] — **المرجع:** [ ] — **الدليل:** [رابط لقطة أو ملف]

### T3 — دورة الاعتماد الكاملة

**الهدف:** إثبات أن كل دور ينفذ مرحلته فقط وبالترتيب المعتمد.

**الحسابات:** محاسب [ ]، مراجع [ ]، مدير مالي [ ]، مدير عام [ ]، مدقق [ ] حسب السياسة.

**خطوات التحقق:** إنشاء وإرسال الطلب بالمحاسب، تنفيذ كل مرحلة من الحساب المخصص لها، تسجيل الخروج بين الحسابات، تجربة إجراء غير مسموح بحساب غير مخصص، ثم مراجعة سجل التدقيق.

**معيار القبول:** لا يوجد اعتماد ذاتي أو تجاوز غير مصرح به، ويتغير المسؤول التالي بعد كل انتقال، ويظهر حدث تدقيق لكل إجراء.

**النتيجة:** [ناجح / فاشل] — **المرجع:** [ ] — **الدليل:** [رابط سجل التدقيق]

### T4 — المعاينة والطباعة

**الهدف:** إثبات أن المستندات تعرض بيانات الطلب الحالي والكليشة الرسمية بصورة قابلة للاستخدام.

**القوالب:** أمر صرف، سند صرف، تقرير اعتماد، بطاقة أرشفة.

**خطوات التحقق:** فتح الطلب المنفذ، فتح كل قالب، مراجعة الرقم المرجعي والشركة والمستفيد والمبلغ والعملة والقناة والحساب البنكي عند الحاجة ومراحل الاعتماد، الحفظ PDF، ثم الفحص على الكمبيوتر والجوال.

**معيار القبول:** لا توجد بيانات ثابتة أو بيانات طلب آخر، ويظهر الشعار واسم الشركة والبيانات القانونية، ويكون المستند واضحاً RTL ومناسباً للطباعة A4.

**النتيجة:** [ناجح / فاشل] — **المستندات:** [روابط الملفات]

### T5 — الدخول والخروج والصلاحيات

**الهدف:** إثبات عزل الجلسات واحترام الأدوار وإدارة الحسابات المحلية.

**خطوات التحقق:** الدخول بالحساب المحلي، التأكد من الاسم والدور، الخروج، محاولة فتح صفحة محمية بعد الخروج، الدخول بحساب آخر في جلسة مستقلة، تجربة رمز خاطئ، تعطيل حساب اختبار، إعادة تفعيله، واختبار تغيير الرمز المؤقت إن كان مفعلاً.

**معيار القبول:** لا توجد شاشة بيضاء أو جلسة عالقة، ولا يمكن الوصول بعد الخروج، ويُرفض الحساب المعطل والرمز الخاطئ، وتُحترم صلاحيات الواجهة والخادم.

**النتيجة:** [ناجح / فاشل] — **الحسابات المختبرة:** [أسماء الأدوار فقط]
